# audesp_api

Flutter Windows desktop app for sending data to AUDESP (TCE-SP).

## Prerequisites

- **MySQL 8.0** — `docker compose up -d` provides it (user `audesp`/`audesp`, DB `audesp`)
- **`config.ini`** (root, tracked in git) — read at runtime for DB connection alongside the executable or CWD

## Commands

```bash
flutter run                        # launch on Windows
flutter test                       # all tests
flutter test test/path/to/file.dart # single test file
flutter analyze                    # lint (uses flutter_lints)
```

`dart run build_runner build --delete-conflicting-outputs` is available but **not currently needed** — models are hand-written with `fromMap`/`toMap`, not freezed.

## Architecture

- **State:** Riverpod (`flutter_riverpod`) — one provider file per feature, DAOs via `Provider`, services via `Provider`
- **Router:** `go_router` com `ShellRoute` + rail (`shell/widgets/app_navigation_rail.dart`); módulos, ordem e permissões ficam em `core/navigation/app_modules.dart`. A casca envolve Estimativa/Edital/Licitação/Ata/Ajuste/Logs. `homeLocationFor(user)` é síncrono: primeiro módulo de envio acessível, depois Estimativa, Logs ou Perfil. Após login e na abertura com sessão, `home_navigation.dart` escolhe o primeiro módulo de envio com pendência (Edital → Licitação → Ata → Ajuste), com limite de 2 segundos e fallback em caso de erro. O resultado é ignorado se a sessão mudar ou o usuário navegar durante a consulta; mudanças de ambiente recalculam as pendências pelo provider. Login, Perfil e Admin ficam fora da casca.
- **Pattern per feature:** `providers.dart`, `services/`, `pages/`, `widgets/`, optional `domain/` (domain logic) and `csv/` (import parsers)
- **Auth:** local DB users (SHA-256 + pepper). Admin user is seeded on first DB initialization. `AuthService` keeps the AUDESP token in memory with user, environment and expiration; reuse requires a 60-second validity margin (unknown expiration: until 401). Logout, environment changes and HTTP 401 clear it. Sending still requires confirmation, with a password only when no valid token exists.
- **Vínculos e dependências:** `processo/domain/processo_rules.dart` mantém as regras dos formulários. `documentosProcessoProvider` carrega os quatro tipos de documentos, inclusive ajustes sem edital; invalidar após criar, alterar, excluir ou retornar a rascunho. `enviosProcessoProvider` expõe `EnviosProcesso` com os quatro índices de `enviosProvider` e o ambiente ativo. `processosProvider` agrupa esses dados por edital e acrescenta o resumo da Estimativa (`EstimativasDao.listResumo`). Invalidar `enviosProvider` recalcula as conclusões e as pendências. A tela Processos e a cadeia visual de etapas foram removidas.
- **Pendências por módulo:** `pendencias/domain/pendencias_modulos.dart` contém funções puras usadas por `pendenciasModulosProvider` nas abas Pendências (selecionadas inicialmente); os botões flutuantes de criação dos quatro módulos só aparecem na aba Rascunhos e por `pendenciasContagemProvider` nos badges do rail e na tela inicial. Edital reúne compras do PNCP sem edital e protocolos em análise/rejeitados/excluídos (inclusive retificações pendentes de documentos já armazenados); Licitação reúne esses protocolos e editais concluídos sem nenhuma licitação. Ata reúne protocolos e atas do PNCP ainda sem ata local; Ajuste reúne protocolos e contratos do PNCP ainda sem ajuste local. Só atas e contratos liberados contam no badge e na tela inicial; bloqueados aparecem abaixo dos liberados na aba. Ajustes de adesão sem edital também são avaliados. Rascunhos sem envio aceito não são pendências de protocolo. A busca não altera os badges; dispensados não contam; compras dispensadas só aparecem com "Mostrar dispensadas" (Edital), atas e contratos dispensados nunca aparecem. Atualização manual de protocolos consulta direto com token válido do usuário/ambiente ou usa `showAudespAuthDialog`, salva em `ApiLogsDao.updateProtocoloInfo` e invalida `enviosProvider`.
- **Env switching:** Piloto (`https://audesp-piloto.tce.sp.gov.br`) / Oficial (`https://audesp.tce.sp.gov.br`), persisted in `app_settings` table
- **Reports:** Uses the `pdf` package for generating exportable PDF reports (e.g., system logs).

## Database

- Schema **auto-creates** on first `DatabaseService.initialize()` with versioning via `__schema` table (current: v19); migrations are the `if (version < N)` blocks in `database_service.dart`
- Tables: `users`, `editais`, `licitacoes`, `atas`, `ajustes`, `app_settings`, `api_logs`, `estimativas`, `assinaturas_predefinidas`, `xsd_comissao`, `xsd_licitacao_logs`, `xsd_licitacao_profiles`, `pncp_compras`, `condutores`, `pncp_contratos`, `pncp_atas`
- **Access:** DAOs use `DatabaseService.execute` (no parameters, or client-side named parameters) and `DatabaseService.executePrepared` (server-side binding; always deallocates). Never prepare a statement elsewhere: open statements only die with the connection, `max_prepared_stmt_count` is global to the MySQL instance, and a leak here takes down the other systems on that server.
- **Pool:** `DbPool` (`db_pool.dart`) replaces the driver's `MySQLConnectionPool`, which exceeds `maxConnections` in bursts, freezes the isolate when no connection is idle (`pool.dart` `Future.doWhile`) and loses the connection when a `withConnection` callback throws. `DbPool.use` holds a connection exclusively, so a callback must not call `DatabaseService` again.
- Timestamps are **Unix epoch seconds** stored as `BIGINT`
- `documento_json` stored as `LONGTEXT` (raw JSON string)
- `app_settings` is a key-value store (`SettingsKeys` constants in `app_settings_dao.dart`)
- Unique index on `users.email(255)`
- `estimativas.status` stores the local state; nullable `editais.estimativa_id` has no FK (deleted source estimates are handled as absent).

## Notable Conventions

- **Admin user:** seeded in `users` table automatically during DB initialization.
- **Logs:** accessible only with a sending permission (Edital/Licitação/Ata/Ajuste). API logs in `api_logs` are read-only in the UI; deletion is restricted for auditing. Logs can be exported to PDF.
- **Último envio:** `api_logs` has no document id; a send is matched to its document by the `descritor` fields (`DescritorEnvio` in `logs/domain/ultimo_envio.dart`, also used by the forms' `findLatest*SendLog`). The list pages load `ApiLogsDao.listEnvios`, which extracts only the descritor in MySQL (`JSON_EXTRACT`), and show `UltimoEnvioChip` on each card, drafts included (failed attempts, rejected protocols).
- **Password hashing:** SHA-256 with email + pepper (`'audesp_api_sys_2026'`), done in `PasswordHasher`
- **Document status:** `'draft'` (editing) vs `'sent'` (submitted to AUDESP). Status can also be consulted via the AUDESP Protocol Status Consultation feature.
- **Estimativa:** `'rascunho'` (editable) vs `'finalizada'` (read-only; PDF/HTML remain available). Only finalized estimates can be imported into an Edital. Reopening warns about linked editais without changing their imported items. Migration v13 finalizes existing estimates.
- **Gemini default model:** hardcoded as `'gemini-3.1-flash-lite'` in `GeminiService`; API key configured via Admin UI → stored in `app_settings`
- **AUDESP API auth:** email:password → POST `/login` → returns `access_token`, attached as `Authorization: Bearer <token>` by Dio interceptor (`ApiService`)
- **CSV parsers** support UTF-8 (with/without BOM) and Latin-1; use `CsvUtils` (`lib/core/utils/csv_utils.dart`)
- **Edital "Sem PNCP"** (`Edital.semPncp`): the edital uses a local `codigoEdital` instead of the PNCP id. Contracts (Ajuste) and Atas derived from it are not on PNCP either, so their forms switch `codigoContrato` / `codigoAta` to free local codes (max 25 / 31 chars) instead of the masked PNCP field. Use `text.trim()` (not `PcnpInputFormatter.stripMask`) for local codes.
- **SRP:** following the prefeitura's practice, an SRP edital generates only Ata, and a non-SRP edital generates only Ajuste. Although TCE-SP allows Ajuste from Ata, the system does not offer that flow. The Ata form only lists sent SRP editais; the Ajuste form only lists sent non-SRP editais. Adesão/participação follows its separate flow.
- **Fase concluída = protocolo armazenado:** a phase only unlocks the next one when a send of the document (original or retificação, matched by the descritor without `retificacao`) is **Armazenado** (or Substituído) in the active environment — `ConclusaoEnvio` in `logs/domain/conclusao_envio.dart`; `status = 'sent'` alone is not enough. A Piloto protocol never concludes in Oficial. Legacy: `'sent'` with no accepted send log counts as concluded. A later retificação em análise/rejeitada does not undo it. A sent Ajuste whose latest protocol is stuck at "Recebido" (an AUDESP problem; `protocoloPodeSerReenviado`) offers "Reenviar": the stored document is sent again and gets a new protocol, the old one stays in the logs. The Ajuste list shows `ReenviarRecebidosButton` (badge with the count) when `AjusteRecebido.listar` finds any (active environment, not concluded, edital not hidden) and resends them all, continuing past individual errors. Besides "Recebido" it lists sent ajustes whose latest protocol was rejected **only** by RN012_AJUSTE while the stored document still uses `dataVigenciaInicio` (`EnvioResumo.codigosErro` comes from `retorno_status.erros[*].codigoErro` in `listEnvios`). Blocking reasons show the protocol situation.
- **Retificação:** a stored document (concluded in the active environment) offers "Retificar" in its form: it goes back to draft with `retificacao = 1` (`*Dao.iniciarRetificacao`) and is sent again with `descritor.retificacao = true`. The flag is no longer a free choice: `RetificacaoRules.modo` (`logs/domain/retificacao.dart`) imposes `true` when the environment already has a stored send, `false` when it has accepted sends but none stored (rejected original), and leaves the checkbox free only without accepted sends or for legacy documents (document provided by another system). Forms recompute it on open, save and send (`_atualizarConclusao`, via `EnviosProcesso.porDescritor`). In a retificação draft the codes AUDESP forbids changing (`codigoEdital`, `codigoAta`, `codigoContrato`) and the edital link are locked, and the draft cannot be deleted from the listing. `ConclusaoEnvio.retificacao` holds a retificação sent after the stored version and still em análise/rejeitada: the phase stays concluded and dependents stay released, but it counts as a pendência (`PendenciasRules.protocoloPendente`) and blocks a new "Retificar". "Descartar retificação" (draft, or rejected retificação) restores the stored version from `api_logs.request` of the stored send (`versaoArmazenada`) and sets `retificacao_descartada_em` (v19, the four document tables), which makes earlier retificação sends stop counting as pending; the edital PDF path is not restored. The form header shows the pending retificação or the stored send (`logDoCabecalho`). Licitação and Ata no longer inherit the edital's `retificacao` flag.
- **Protocolos em andamento:** `protocolosMonitorProvider` (shell, users with Logs access) consults up to 20 non-final protocols of the active environment every 2 minutes, only while `AuthService.tokenValido` holds (it never asks for the password), and invalidates `enviosProvider` when one changes.
- **Dependencies:** Licitação can only be sent with the edital concluded; Ata requires a concluded SRP edital and concluded Licitação; Ajuste requires a concluded non-SRP edital and concluded Licitação, except adesão/participação. Legacy ajustes linked to an Ata or SRP edital remain visible and editable, preserving their stored ata_id; only sending is blocked.
- **Ajuste de adesão/participação:** `ajustes.edital_id` is nullable (v12). With `adesaoParticipacao = true` the local edital link is optional and `codigoEdital`/`codigoAta` are typed PNCP ids of the managing entity; `Ajuste.editalId` is `int?`, so code reading it must handle null.
- **PNCP:** `features/pncp/` consulta a API pública (`/v1/orgaos/{cnpj}/compras/{ano}/{sequencial}`, 404 = sem compra) para o CNPJ de Admin → PNCP / UFESP. `PncpVarredura` parte da última sequência encontrada (settings `pncp_sequencia_<cnpj>_<ano>`), para após 3 respostas 404 consecutivas ou 50 requisições e só consulta o ano anterior se já consultado. **Corte:** o sistema vale só para editais publicados a partir de 02/02/2026 e as atas/contratos derivados (`PncpVigencia`): compras anteriores, e atas/contratos cuja compra foi publicada antes (pela `pncp_compras`; senão compra de ano < 2026 ou assinatura antes do corte), nunca geram pendência, nem entre as dispensadas; continuam salvos. O admin ajusta ali os cursores do ano atual de compras, contratos e atas (`PncpCursores`: ata ≤ compra; só o que mudou é gravado; mudar o de atas move `pncp_atas_atualizadas_ate` para hoje e limpa a página em andamento). 410 é ignorado sem contar como ausência; 429 aguarda `Retry-After` (≤ 60 s, padrão 10 s) e tenta uma vez; outros erros preservam o progresso e aparecem no botão "Consultar PNCP" da listagem de Edital. O botão só aparece com PNCP configurado e permissão de criar edital; mostra execução, erro e última consulta. Compras em `pncp_compras` sem edital correspondente (`codigoEdital` ou publicação PNCP, só dígitos) aparecem em Edital → Pendências para quem cria edital. Na interface só podem ser dispensadas (motivo opcional) quando o envio não é obrigatório pela UFESP (`UfespConfig.envioObrigatorio`); as demais, só no banco (preencher `pncp_compras.dispensada_em`). Todas podem ser restauradas via "Mostrar dispensadas". "Iniciar edital" abre `/edital/new?pncpCompraId=` com o cabeçalho de `PncpEditalMapper`, sem importar itens. `pncpMonitorProvider` continua na casca, verifica a cada minuto e só consulta quando `pncp_ultima_consulta_em` ultrapassa o intervalo configurado, compartilhado entre máquinas.
- **Contratos PNCP** (v17): na mesma rodada de `PncpConsultaNotifier`, depois das compras, consulta `/api/pncp/v1/orgaos/{cnpj}/contratos/{ano}/{sequencial}` (não `/api/consulta`). `PncpVarredura.executarContratos` compartilha o algoritmo das compras, com limite próprio de 50 consultas e cursor `pncp_contrato_sequencia_<cnpj>_<ano>`; usa a mesma `pncp_ultima_consulta_em`. Falhas preservam tudo já salvo e a mensagem de sucesso informa compras e contratos novos. `ConsultarPncpButton` também aparece no Ajuste com a respectiva permissão. `PncpContratosDao.upsert` preserva a dispensa. `PncpContratosPendencias.classificar` casa códigos com dígitos: qualquer ajuste local, inclusive rascunho, retira o contrato das pendências; referência a ata, edital SRP ou oculto nunca aparece, nem nas dispensas. Adesão (`frutoAdesao` ou compra de outro CNPJ) é liberada sem dependência local; nos demais casos usa `ProcessoRules.motivoBloqueioAjuste`. Sem compra PNCP, bloqueia mesmo na adesão, pois falta a referência do edital. Contratos não são dispensados pela interface: a dispensa (e a restauração) é feita só no banco, em `pncp_contratos.dispensada_em`/`dispensada_por`/`motivo_dispensa`; dispensados não aparecem na aba. `/ajuste/new?pncpContratoId=` revalida a pendência e aplica `PncpAjusteMapper` à resposta salva, sem consultar novamente a rede: referências, número/ano, processo, fornecedor, objeto, datas e valores presentes; tipo e categoria apenas nos enums do schema AUDESP. Não deduz itens, fontes, despesas, tipo de objeto nem dados da gerenciadora.
- **Atas PNCP** (v18): depois das compras e contratos, `PncpAtasVarredura` lista `/api/pncp/v1/orgaos/{cnpj}/compras/{ano}/{sequencialCompra}/atas`, sem usar o SRP do PNCP. O cursor `pncp_ata_compra_sequencia_<cnpj>_<ano>` nunca passa do cursor das compras; 204/404/410 avançam sem interromper. Ano anterior só quando há cursor de compras. Há limite próprio de 50 páginas por rodada; `pncp_ata_compra_pagina_<cnpj>_<ano>` guarda `sequencialCompra:proximaPagina` para retomar compras paginadas sem saltá-las. Na mesma rodada consulta todas as páginas de `/api/consulta/v1/atas/atualizacao` (100 registros/página e 90 s de limite, pois o endpoint oscila muito; tempo esgotado tenta a mesma página mais uma vez, como nas demais consultas ao PNCP), do marcador `pncp_atas_atualizadas_ate` menos um dia até hoje, limitado aos últimos 365 dias inclusivos; sem marcador, começa em janeiro do ano atual. O marcador só avança após salvar toda a janela e `pncp_atas_atualizadas_cnpj` impede reutilizá-lo para outro CNPJ. `PncpAta.fromApi` normaliza lista/detalhe e atualização, deriva a compra dos 25 primeiros dígitos e confere a URL quando disponível. Upsert por controle preserva dispensa e atualiza cancelamento/vigência. `PncpAtasPendencias.classificar` retira atas locais de qualquer status, ignora editais ocultos e canceladas, mantendo canceladas dispensadas restauráveis. Só libera com edital local SRP e `ProcessoRules.motivoBloqueioAta` sem bloqueio. A listagem permite consultar e lançar via `/ata/new?pncpAtaId=`; atas, como contratos, só são dispensadas/restauradas no banco (`pncp_atas.dispensada_em`) e dispensadas não aparecem; a rota tenta atualizar o detalhe, usa a leitura salva em caso de falha e revalida antes de preencher. `PncpAtaMapper` importa códigos, ano da compra, número/ano da ata e datas presentes no schema; não deduz itens nem outros dados.
- **Edital oculto** (v15: `editais.oculto_em`, `oculto_por`, `motivo_ocultacao`): identifica processos enviados por outro sistema; nada é excluído. Não gera pendências em nenhum módulo, inclusive para documentos vinculados, e bloqueia nova licitação/ata/ajuste (`ProcessoRules.motivoEditalOculto`, também na adesão). Fica fora de `EditaisDao.watchByStatus` e do seletor de Licitação, salvo vínculo existente. `documentosProcessoProvider` e `processosProvider` o preservam para corresponder às compras do PNCP e verificar dependências, mas ele não aparece nas pendências. **Ocultar/restaurar é feito só no banco** (preencher/limpar `oculto_em`); não há ação nem lista de ocultos na UI.
- **Documentação AUDESP monitorada:** `features/documentacao/` verifica a página de JSON Schemas/xlsx do TCE e a API (`audesp.yaml`, carregado pela casca do Swagger em `/api`) uma vez por período (0h–12h / 12h–0h, `periodoVerificacao`), compartilhado entre as máquinas via `app_settings` (`documentacao_*`). Compara hashes SHA-256 do texto do `<article>` (menu/rodapé mudam sozinhos), de cada anexo e do yaml. A primeira leitura vira referência; diferença mostra um ícone vermelho no rail para todos ("informe o TI") e só o admin "Marcar como verificada" (referência = última leitura). Falhas são silenciosas e liberam o período, com nova tentativa após 15 min.
- **UFESP:** `UfespConfig` (`processo/domain/ufesp_rules.dart`, settings `ufesp_valor` / `ufesp_quantidade_minima`, padrão 2.500 × R$ 38,42). `UfespIndicador` fica em `shared/widgets/ufesp_indicador.dart` e mostra "Envio não obrigatório" em compras do PNCP e editais abaixo do limite, na listagem e nas pendências (inclusive criar licitação). O indicador é informativo e não altera pendências nem badges. `Edital.valorTotalEstimado` soma `itensCompra[].valorTotal`.
- **Prazos AUDESP:** `PrazoEnvioConfig` / `PrazosEnvio` (`pendencias/domain/prazo_envio.dart`), settings `prazo_*`, aba Admin → Prazos AUDESP. Edital cuja compra foi publicada no PNCP antes do corte (padrão 01/11/2026) tem prazo fixo (padrão 01/02/2027), também para atas e ajustes dele; depois, dias úteis sem contar o dia base: edital 5 da publicação da compra, ata 15 e ajuste 22 da assinatura (sem ela, da publicação). Licitação não tem data de referência e fica sem prazo. O regime vem da publicação da compra em `pncp_compras`; sem ela, da data do próprio documento. `DiasUteis` exclui fins de semana, feriados nacionais, 09/07, Sexta-feira Santa, Carnaval/Corpus Christi (opcionais) e as datas extras do admin (`dd/MM` anual ou `dd/MM/aaaa`). `PrazoEnvioIndicador` (`shared/widgets`, só o ícone, com o texto na tooltip, como `UfespIndicador`, via `IndicadorIcone`) aparece nos cartões de compras/atas/contratos do PNCP e nos protocolos pendentes de edital/ata/ajuste que casam com o PNCP, nunca em dispensados ou atas canceladas; as listas do PNCP vêm ordenadas pelo prazo (bloqueados abaixo). É só informativo: não altera pendências, badges nem envios.
- **Condutores** (v16, `condutores`: nome + CPF único): cadastro reutilizável para `cpfsCondutores` da Licitação, escolhido em `licitacao/widgets/condutores_dialog.dart` (como as assinaturas da exportação SEI). A licitação continua guardando só os CPFs; CPFs fora do cadastro (anteriores a ele ou excluídos dele) permanecem na licitação (`CondutorRules.aplicarSelecao`).
- **Licitante `niPessoa`:** use `normalizarNiPessoa` (`licitacao/domain/licitacao_pessoa.dart`). The function keeps digits and uppercase letters for PJ, keeps digits for PF and trims outer whitespace for PE. The Ajuste form uses the same CNPJ rule when saving the main supplier as PJ.

## AUDESP documentation

- Official docs live in `docs/tcesp/`: one folder per document with JSON schema + example (`edital-20261015/`, `licitacao-20261015/`, `ajuste-20261015/`, `ata-20261015/`, `empenho-20261015/`), the HTTP contract `audesp.yaml`, and the rules/domains spreadsheet `Novo Modelo da Fase IV_2026_v04_externo.xlsx` (sheet "Alterações" is the changelog).
- **The JSON schema is what the server validates.** When the spreadsheet lists domain codes the schema enum lacks (e.g. amparos 174–189, fonte de recurso 19/99), follow the schema and leave a comment in the domain file.
- O schema do Ajuste e a RN010_AJUSTE usam `dataVigenciaInicio`. A RN012_AJUSTE cita `datavigenciaInicio`. O formulário e `PncpAjusteMapper` salvam `datavigenciaInicio`, e `AjusteDocumento` (`ajuste/domain/ajuste_documento.dart`) lê as duas grafias. `AjusteService.enviarAjuste` inclui ambas com a mesma data quando há início de vigência, em envios e reenvios.
- Domain constants are in each feature's `domain/*_domain.dart`; conditional rules (e.g. Ajuste fontes, despesas, vigência) in `domain/*_rules.dart` with unit tests.
- `docs/compatibilidade-audesp-20261015.md` is the compatibility review of the 15/10/2026 update, with the status of each finding.
- The Empenho module is not used by the app for now.

## Testing

- Tests under `test/` mirror `lib/` (domain rules, CSV parsers/mappers, services, models, some shared widgets).
- CSV tests use `flutter_test` with inline byte fixtures (`utf8.encode`, `latin1.encode`); `CsvParseException` from `csv_utils.dart` is expected in error cases.
- Database tests run the real driver against `test/support/fake_mysql_server.dart`, a local socket server that counts statements and connections; no MySQL is needed.
- Prefer extracting business rules into pure functions in `domain/` and testing them there; widget tests are only used for shared widgets and import dialogs.

## Gotchas

- `config.ini` contains real DB credentials and **is tracked in git** — do not commit changes to it unless intentional
- `freezed` / `json_serializable` are declared in `pubspec.yaml` but **no generated files exist** — all models use manual `fromMap`/`toMap`
- On first run the DB schema auto-creates (`__schema` table) and the default admin user is seeded automatically.
- `flutter_secure_storage` uses DPAPI on Windows with `useBackwardCompatibility: false`
